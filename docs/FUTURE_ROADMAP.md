# AG-MONITOR 未來發展藍圖與技術優化計畫

這份文件記錄 `AG-MONITOR 智慧影像快篩系統` 的技術演進、歷史里程碑與後續實作方向。

---

---
✅ **[已完成] 介面效能解放：前後端渲染剝離 (v3.0)**
*已於 v3.0 版本成功實作，將 YOLO 追蹤框的渲染任務全面移交至前端 HTML5 Canvas 透過 GPU 硬體加速繪製，解除 Python 後端 CPU 運算與影像傳輸的瓶頸，達成 60FPS 極致流暢。*

✅ **[已完成] 系統強健度：看門狗防禦機制 (Watchdog Timer)**
*針對實務辦案中硬碟物理性壞軌導致的解碼死鎖 (Deadlock)，建立獨立的 Watchdog 執行緒監控心跳。遇異常時啟動強制熔斷 (Emergency Break) 與自動略過，確保整晚的批次分析絕不中斷。*
  - 系統捕獲異常後，自動放棄該檔案、回報介面錯誤摘要，接著跳轉分析下一個影片；現行快篩流程不再建立鑑識文字紀錄。
  - **預期效益**：確保無人值守的「過夜批次處理」絕對不會因為單一壞檔而整晚停擺。

## 3. 🧠 追蹤演算法進化：特徵重新識別 (ReID)
目前系統使用的 `ByteTrack` 追蹤演算法，主要依賴卡爾曼濾波 (Kalman Filter) 計算物體的運動軌跡來維持 ID。
* **痛點**：在「下班塞車潮」等極度擁擠的情境下，若機車被公車完全遮蔽超過 3 秒後才重新出現，系統容易丟失目標並賦予其全新的 ID。
* **改進細節**：
  - 將純運動學追蹤器升級為具備「外觀特徵提取」的追蹤器，例如 `BoT-SORT` 或 `DeepSORT`。
  - AI 不僅記錄車輛軌跡，還會記錄車輛的「顏色、形狀特徵向量 (Feature Vector)」。
  - **預期效益**：大幅降低 ID Switch (目標切換) 的機率，即使車輛被大型障礙物遮蔽後再出現，依然能被系統精準認出並維持同一個追蹤 ID。

**2026/08/12 P3-1 進度**：已加入白名單式 BoT-SORT ReID 實驗選項，採 YOLO 原生外觀特徵且保留 ByteTrack 為預設。CH09 實體片段雙輪代理基準顯示短軌跡與相鄰幀 ID 變更均略降；尚待人工標註遮蔽案例驗證，暫不升級為預設。
