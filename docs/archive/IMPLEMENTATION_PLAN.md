# AG-MONITOR P2 鑑識強化實作計畫

> 歷史封存說明：本文件前半部保留 P2／P3 的實作與驗證紀錄。Real-ESRGAN、鑑識文字紀錄及截圖清冊已於 2026-08-28 的 P4 快篩化重構中退役；現行規格以 P4 區塊、`README.md` 與 `CHANGELOG.md` 為準。

## 目標與驗收條件

- AVI 檔名 `CH07-20260326-173728-184505.avi` 可解析為 `2026-03-26 17:37:28`，截圖時間碼使用實際時間。
- 批次重新命名先完成來源雜湊與目的路徑規劃，禁止覆寫；失敗時回復已執行項目，並產生可供人工回復的 UTF-8 紀錄。
- 看門狗只在解碼階段無進展時熔斷，不把佇列背壓或 YOLO 推論時間誤判為解碼死鎖，並保留慢速解碼診斷。
- Real-ESRGAN 下載檔通過固定 SHA-256、ZIP 路徑安全及必要檔案驗證；支援取消、暫存檔隔離、Vulkan 執行與 OpenCV 備援。
- 四支 `input_videos/` 實體影片完成全批次測試，留下耗時、輸出數量、記憶體與鑑識紀錄結果；不修改原始影片。
- 整合 `origin/main` 的遠端啟動防禦意圖，保留本地固定版本驗證與可攜修復能力。

## 不做範圍

- 不重新訓練 YOLO 或超解析模型。
- 不變更原始證物內容；重新命名測試只使用臨時複本。
- 不推播 GitHub，除非使用者另行要求。
- 不進行 `main.py` 大型模組拆分。

## 現況與限制

- 工作分支 `main` 已有乾淨提交 `5e16c2f`，相對 `origin/main` 為 ahead 1、behind 1。
- 四支測試影片總計約 3 GB，完整 YOLO 批次可能長時間占用 CPU 並產生大量截圖。
- `models/realesrgan/` 尚不存在，首次實測需要下載官方 NCNN Vulkan 發布資產。
- `python-embed/`、模型、輸入影片及輸出資料均由 `.gitignore` 排除。

## 已確認決策

- AVI 格式以獨立、具邊界的正規表示式解析，不改變既有格式優先順序。
- 重新命名採「先規劃與雜湊、再執行、失敗反向回復」；目的檔已存在時產生唯一名稱，不覆寫。
- 看門狗追蹤解碼器階段；等待消費端取走佇列資料時視為正常背壓。
- 超解析 ZIP 必須固定雜湊並拒絕絕對路徑、`..` 與連結型項目。
- 長時間測試輸出放在 `captures/`，完成後只保留報告與必要抽樣；大量測試截圖是否清理由實際容量決定並先盤點。

# P4 快篩化重構計畫（功能已實作，實體影片驗證待補）

## 目標與驗收條件

- 移除自動分析流程的影片 SHA-256、鑑識報告與截圖 JSONL 清冊；加入影片後不得因全檔讀取而延遲排入分析。
- 保留 PyAV 裸流容錯、解碼看門狗、空景快轉、ROI、多目標去重、騎士融合與靜止目標過濾。
- 支援白名單模型 `yolo11n.pt`、`yolo11s.pt`、`yolo12n.pt`、`yolo12s.pt`，並保留既有 YOLOv8 作為相容性回退；640／960／1280 推論解析度維持可選。
- 新截圖預設為完整原解析度、未裁切、未烙印的全景 JPEG；勾選標註時才以副本繪製同波所有目標框與類別文字。
- 已確認移動的新 Track ID 必須觸發場景截圖；同一波新目標合併為一張，已記錄 ID 在未重新進入前不可重複觸發。
- 截圖編碼與檔案寫入須由有界非同步 Writer Queue 處理；推論執行緒不得直接執行 `cv2.imwrite` 或等效同步落檔。
- Headless 批次模式不得傳送 Base64 預覽或逐幀 UI 回呼，仍須支援中止、錯誤摘要與完成狀態。
- 使用至少一段日間車流、一段夜間眩光與一段含樹影或固定雜訊的實體影片，驗證 ROI、靜止過濾、場景合併、檔名與停止收尾行為。

## 不做範圍

- 不重新訓練 YOLO 模型，不宣稱演算法可達絕對零漏檢。
- 不移除安全批次重新命名功能；該功能的雜湊交易與自動分析流程分離。
- 不改寫為 OpenCV 解碼或 CustomTkinter，不從參考系統的封裝 EXE 反向取得程式碼。
- 不平行處理多支影片以競爭單一 GPU；本階段先改善單一影片管線與批次無頭通道。

## 現況與限制

- 自動分析流程已不再計算影片 SHA-256，也不再建立截圖 JSONL 清冊與鑑識報告；安全批次重新命名仍保留交易前後雜湊核對。
- 前端與後端均支援 640／960／1280，模型白名單已加入 YOLO11／12 並保留 YOLOv8 相容回退。
- 截圖已改為原解析度全景 JPEG，預設乾淨原圖；勾選後才在副本烙印同波所有目標框。
- 批次流程仍採逐支影片隔離子程序；Headless 會停止 Base64 預覽與逐幀目標狀態，只保留進度、Writer 摘要與錯誤訊息。
- 可攜執行環境已安裝並驗證 `ultralytics 8.4.67`，套件內含 YOLO11／12 架構；專案目前只有 `yolov8n.pt`，四個 YOLO11／12 權重仍須另行放入專案根目錄後實測。
- 專案目前沒有 `input_videos/` 實體測試片段，日間、夜間眩光與樹影／雨天量測尚不能完成。

## 已確認決策

- 採 A+B 融合：保留 AG-Monitor 的 PyAV、ROI、追蹤與空景快轉；吸收 Reader → Infer → Writer 分流及 Headless 批次概念。
- 截圖檔名格式採 `{影片名稱}_{時間碼}_ID{首個觸發目標ID}_{類型}.jpg`；同波其他新目標併入同一張全景圖。
- 原始 BGR frame 不可被標註流程修改；標註截圖一律由原圖複本生成。
- 動態引導須以 ROI 內像素移動作為第二道訊號，並經最小尺寸與連續幀確認；初始預設為面積至少 500 像素、連續至少 2 幀，且只將補償區域的 YOLO 門檻由 0.35 降至 0.18，不得僅因 YOLO 已有框便稱為動態引導。
- Writer Queue 滿載時採「不靜默丟圖、同波合併、必要時短暫背壓並回報狀態」。正常分析結束時必須排空佇列；使用者點擊強制停止時，立即清空尚未寫入的事件並斬斷處理程序，以秒級回應優先。
- 「不漏抓」的驗收定義為：已被追蹤器確認的新移動目標必定建立場景截圖事件；模型未偵測到的目標不列入絕對保證。

## UI／UX 規格

- 主畫面維持「加入影片 → 設定 → 開始分析 → 檢視截圖」的單一工作流；不新增獨立複雜頁面。
- 在開始按鈕上方提供明確執行模式二選一：`即時檢視`（預設，顯示預覽與 ROI）及 `全速快篩`（Headless，不傳送逐幀畫面）。模式說明須直接標示速度與可見性的差異。
- 模型、推論解析度與信心門檻置於「辨識設定」；YOLO11n＋960 作為一般路口的預設建議，模型不存在或 runtime 不相容時禁止開始並提供可讀錯誤。
- 截圖設定獨立為「輸出規則」：預設 `全景原圖`，可勾選 `烙印 AI 標註框`；同區以說明文字揭露「同波新目標合併為一張」。
- ROI 操作維持畫面點選、清除與即時預覽；全速快篩若尚未設定 ROI，仍可分析整張畫面，不能造成無法開始的阻塞。
- 分析期間固定顯示：目前影片、處理時間碼、偵測事件數、已寫入張數、Writer Queue 深度及狀態（正常／寫入落後／排空中）。Headless 只顯示此摘要，不顯示 Base64 預覽。
- 停止操作拆為兩個語意清楚的按鈕：`停止並完成寫入`（一般停止，排空佇列）及危險樣式 `強制停止`（立即捨棄未寫事件）。強制停止完成後須在結果摘要顯示已捨棄數量。
- 分析中鎖定會改變模型、解析度、ROI 與輸出規則的設定；保留「開啟截圖資料夾」與停止控制，避免執行中的設定與實際管線不一致。
- 完成摘要顯示輸出資料夾、場景事件數、實際完成寫入數、已捨棄數與錯誤數；不以鑑識報告或 JSONL 作為使用者必須理解的產物。

## 風險與因應

- Writer Queue 不可能在磁碟吞吐不足時同時保證零等待與零遺漏；以有界佇列、事件合併與可見背壓處理，禁止靜默捨棄。
- YOLO12 支援取決於可攜環境的實際套件版本與權重；未驗證前保留 YOLOv8 回退，不能只改前端選項。
- Track ID 在遮擋與密集車流中仍可能變更；以 ReID 選項與實體片段回歸量測，避免宣稱 ID 永不重置。
- 背景差分易受夜間大燈、樹影、雨滴與蜘蛛絲干擾；僅在 ROI 內生效並採面積、連續幀與 YOLO 候選三層過濾。

## 風險與因應

- CPU Runtime 未壓縮約 1.3 GB：ZIP 使用一般 Deflate 並驗證低於 GitHub 單一資產 2 GiB 限制。
