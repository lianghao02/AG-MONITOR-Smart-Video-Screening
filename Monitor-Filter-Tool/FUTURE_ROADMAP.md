# AG-MONITOR 未來發展藍圖與技術優化計畫 (Roadmap)

這份文件記錄了 `AG-MONITOR 科技偵查 · 智慧雙軌鑑識工作站` 從當前版本 (v1.1) 邁向「企業級/國家級鑑識系統」的未來潛在改進空間與技術實作細節。

---

## 1. 🚀 效能架構：多執行緒非同步管線 (Async Pipeline)
目前系統在處理影片時，YOLO 模型推論與 PyAV 影像解碼是在**同一個執行緒中序列執行**（解碼一幀 ➡️ 分析一幀）。
* **痛點**：這會導致 GPU (負責 AI) 必須等待 CPU (負責解碼)，造成算力閒置，無法發揮最大效能。
* **改進細節**：
  - 導入 `queue.Queue` 實作「生產者-消費者 (Producer-Consumer)」模型。
  - **生產者執行緒**：專職負責 PyAV 解碼，將解碼完成的影像幀 (Frame) 不斷塞入 Buffer Queue。
  - **消費者執行緒**：專職負責 YOLOv8 推論，純粹從 Queue 中拿取影像進行運算。
  - **預期效益**：徹底榨乾硬體效能，預計批次分析速度可再提升 1.5 倍至 2 倍。

## 2. 🛡️ 系統強健度：看門狗防禦機制 (Watchdog Timer)
針對實務辦案中經常遇到「物理性壞軌」或「檔案結構嚴重損毀」的隨身碟證物。
* **痛點**：極少數極端損毀的 `.dav` 或 `.h264` 檔案，可能會導致底層的 C 語言解碼器 (FFmpeg/PyAV) 陷入死迴圈 (Deadlock)，造成 UI 永久卡死。
* **改進細節**：
  - 建立一個背景監控執行緒 (Watchdog Timer)。
  - 在 `get_frame()` 解碼器前加入計時器。若單幀解碼卡住超過 5 秒未回報，Watchdog 將強制引發 Timeout Exception。
  - 系統捕獲異常後，自動放棄該檔案並寫入 `系統鑑識紀錄.txt`，接著無縫跳轉分析下一個影片。
  - **預期效益**：確保無人值守的「過夜批次處理」絕對不會因為單一壞檔而整晚停擺。

## 3. 📸 數位鑑識修復：引進業界頂流 SR 模型
目前的「數位鑑識照片修復」模組使用了 OpenCV 輕量化的 `ESPCN` 與 `Bilateral Filter`，主打無須安裝龐大依賴且速度極快。
* **痛點**：對於「極度馬賽克」的車牌或人臉，輕量化模型的還原能力有限，僅能做到邊緣銳化。
* **改進細節**：
  - **車牌特化**：無縫整合 `Real-ESRGAN` 或 `BSRGAN` 的 PyTorch 權重檔，能從極度模糊的像素中重建出車牌號碼的邊緣細節。
  - **人像特化**：整合 `GFPGAN` 或 `CodeFormer`，這兩種模型專為人臉修復設計，甚至能將五官完全糊掉的影像還原出清晰輪廓。
  - **預期效益**：鑑識還原能力發生「質的飛躍」，提供法庭上更有力的圖像證據。

## 4. 🧠 追蹤演算法進化：特徵重新識別 (ReID)
目前系統使用的 `ByteTrack` 追蹤演算法，主要依賴卡爾曼濾波 (Kalman Filter) 計算物體的運動軌跡來維持 ID。
* **痛點**：在「下班塞車潮」等極度擁擠的情境下，若機車被公車完全遮蔽超過 3 秒後才重新出現，系統容易丟失目標並賦予其全新的 ID。
* **改進細節**：
  - 將純運動學追蹤器升級為具備「外觀特徵提取」的追蹤器，例如 `BoT-SORT` 或 `DeepSORT`。
  - AI 不僅記錄車輛軌跡，還會記錄車輛的「顏色、形狀特徵向量 (Feature Vector)」。
  - **預期效益**：大幅降低 ID Switch (目標切換) 的機率，即便車輛被大型障礙物遮蔽後再出現，依然能被系統精準認出並維持同一個追蹤 ID。

## 5. 🌐 介面效能解放：前後端渲染剝離
目前的實時預覽畫面，是由 Python 在後台透過 OpenCV 畫好「紅色追蹤框與文字」後，將整張圖片壓縮成 Base64 字串，再透過 WebSocket 傳給前端。
* **痛點**：每秒要壓縮並傳輸 30 張大圖，極度消耗 Python 伺服器端的 CPU 運算力與本機網路頻寬。
* **改進細節**：
  - 將「影像」與「標註框」的資料流分離。
  - Python 端只需傳送「乾淨的影像幀」與「輕量化的座標 JSON 數據 (包含 x, y, w, h, ID)」。
  - 由前端網頁的 HTML5 `<canvas>` 透過瀏覽器硬體加速，即時把框線與文字「畫」在影像上。
  - **預期效益**：降低至少 40% 的 CPU 開銷，實時畫面將能毫無懸念地穩定維持電競級的 60 FPS 流暢度。
