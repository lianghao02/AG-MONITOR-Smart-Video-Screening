# AG-MONITOR 專案領域知識與開發規範

> [!IMPORTANT]
> 本專案受全域開發憲法 v8.0 約束。修改前先讀取專案文件，採最小異動並完成實際驗證。

以下為本專案的業務領域知識與技術限制。

## 1. 軟體元件

- 前端介面：Eel 搭配 HTML、CSS 與 JavaScript。
- 後端辨識：Python、Ultralytics YOLO 與 ByteTrack。
- 影像處理：OpenCV-Python。
- 鑑識輸出必須保留來源檔案、時間碼與雜湊的可追溯性，不得把 AI 結果視為原始證物。

## 2. 智慧空景跳躍

- 無人空景依 `SMART_SKIP_SEC = 3.0` 計算跳幀步長。
- OpenCV 動態偵測使用 `MOTION_THRESH = 25` 與 `MOTION_MIN_AREA = 500` 判斷畫面變化。
- 偵測到變化時必須保留回溯緩衝，避免跳過目標進入畫面的起始片段。
- 修改跳幀邏輯時，必須驗證一般影片、裸流與低畫格率來源。

## 3. 遮蔽後的追蹤識別延續

- ByteTrack 目標短暫離開畫面後，`track_states` 依 `BYTETRACK_OCCLUSION_GRACE_SEC = 1.5` 保留狀態，再由回收流程清理。
- 新識別碼可依最後位置與目標尺寸尋找舊狀態；搜尋半徑維持 `max(80, min(200, max(w, h) * 1.2))` 的上下限。
- `id_alias_map` 負責把短暫跳號的新識別碼映射回舊識別碼，延續最佳畫格與冷卻狀態。
- 不得只為降低重複截圖而無限制延長寬限時間，避免不同目標被錯誤合併。

## 4. 使用影片時間軸

- 截圖冷卻、遮蔽寬限與追蹤逾時以影片內的毫秒時間碼為準，不使用 `time.time()` 取代。
- 時間碼來源應與 `cv2.CAP_PROP_POS_MSEC` 或實際解碼時間軸一致，確保加速、跳幀與離線分析仍可重現。
- 任何時間軸 fallback 都必須寫入鑑識紀錄，且不得把推估值偽裝成精確時間碼。
